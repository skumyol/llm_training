## TODO-1: Fix counterfactual flip temporal corruption

**What:** `src/data_gen/counterfactual.py` applies a variable flip by setting a single midpoint value uniformly to ALL turns in the episode. This erases arc dynamics for the flipped dimension — e.g., `secrecy_pressure` escalating naturally turn-by-turn becomes frozen at one value in counterfactual variants.

**Why:** A student trained on these counterfactuals learns that flipped variables are static across episodes, not dynamic. This directly contradicts the relational arc design and corrupts the training signal for temporal state transitions.

**Pros:** Clean counterfactuals that preserve arc dynamics; stronger augmentation signal; fixes a silent data quality bug.

**Cons:** Requires re-generating the flipped variable per turn (re-run labeling for that variable), which is more expensive than the current single-midpoint approach.

**Context:** The current approach in `CounterfactualAugmenter._apply_flip()` samples the value at the midpoint turn and applies it globally. The fix is to either (a) flip the initial state W and re-run only the affected label step per turn, or (b) constrain counterfactual generation to scenario-type variables (W-level, not per-turn Z_t fields). Found during `/plan-eng-review` outside voice review (2026-03-24).

**Depends on / blocked by:** Not blocking current 500-episode run. Apply before 5000-episode run.

## TODO-2: Add episode-ID cross-check to JointDataset

**What:** `src/training/dataset.py` `JointDataset` zips `train_heads.jsonl` and `train_sft.jsonl` by index, asserting only that record counts match. No episode_id + turn_idx alignment check exists.

**Why:** If any post-processing step (schema revalidation, dedup, secrecy-leak recheck) removes records from one artifact but not the other, training proceeds silently on misaligned data. **Pros:** Eliminates a class of silent training data corruption bugs; takes ~10 lines to fix; makes the pipeline safe to extend with filtering steps.

**Cons:** Minimal — slightly slower dataset initialization (one extra pass to verify IDs).

## TODO-3: Ablate avg-pool vs last-token pooling for classification heads

**What:** `src/training/model.py` `LatentStatePredictor.forward()` extracts the last-token hidden state for all 29 classification heads (`seq_lengths = attention_mask.sum(dim=1) - 1`). On a decoder-only LM, this position is optimized for next-token prediction, not input summarization.

**Why:** Average-pooling over non-padded tokens is more standard for classification heads on causal LMs. If the harder multi-dimensional heads (R_t stance deltas, D_t response policy) underperform their targets, this pooling choice may be a contributor. A 1-run ablation would confirm or rule it out.

**Pros:** Potentially improved R_t/D_t head F1 with no model size increase; publishable ablation result; fixes an undocumented architectural choice.

**Cons:** Adds 1 training run to the experiment grid. Requires modifying `forward()` to implement avg-pool variant.

**Context:** Add a `pooling_strategy: {last_token, avg_pool}` config option to `train_latent.yaml`. Run one extra experiment with `avg_pool` on the best backbone+FT config from the primary grid. Found during `/plan-eng-review` outside voice review (2026-03-24).

**Depends on / blocked by:** Run after primary 15-run experiment grid completes. Needs shared dataset.

## TODO-4: Upgrade secret-leakage validator to semantic matching

**What:** `src/data_gen/validator.py` `_check_secret_leakage()` checks if `secret_id.replace("_", " ")` appears verbatim in the NPC response. Paraphrase leakage (e.g., "the golden vessel in the vault" when `secret_id=chalice_location`) passes silently.

**Why:** A non-trivial fraction of `reveal_decision=none` records in the 5000-episode dataset will contain paraphrased secret leakage. These records poison both training (model learns that `reveal_decision=none` is compatible with revealing the secret in text) and evaluation (secret leakage rate metric is underestimated).

**Pros:** Cleaner training data; more accurate `secret_leakage_rate` evaluation metric; directly improves the paper's core research claim (auditable secret-keeping).

**Cons:** Requires either (a) pre-generating semantic keyword lists per `secret_id` (static, fast), or (b) embedding similarity check per response (dynamic, adds ~50ms per turn). Option (a) is recommended as the minimal fix.

**Context:** The fix: for each secret in the NPC profile, define a `keywords` list in the scenario YAML (e.g., `chalice_location: ["chalice", "goblet", "vault", "lower chamber"]`). Update `_check_secret_leakage()` to check for any keyword match. This is a one-time schema extension. Found during `/plan-eng-review` outside voice review (2026-03-24).

**Depends on / blocked by:** Apply before 5000-episode run. Requires schema.md update and scenario YAML updates.
